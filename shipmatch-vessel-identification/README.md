# ShipMatch · 항만 선박 식별

### 한글 음차와 불완전한 선박 기록을 카탈로그 ID로 연결하는 오프라인 랭킹

항만 기록의 선박명, 호출부호, 톤수, 국적, 선종 등을 이용해 같은 선박을 공식 카탈로그에서 찾는 프로젝트입니다. 선박명이 한글 음차나 약칭으로 기록되거나 톤수와 호출부호가 비어 있어도 후보를 찾을 수 있도록, **문자·발음 기반 검색 → CatBoost 후보 정렬 → Qwen 재정렬 → 근거 검증과 후보 보완**을 결합했습니다.

이 저장소는 제출 파일 `submit_listwise40_1030.zip`의 버전 **`A9715-listwise40-20261030`**을 기준으로 정리했습니다.

## 1. 연구 질문

문자열이 다른 두 이름이 같은 선박을 가리키는지, 이름 외 단서가 누락되거나 서로 어긋나는 상황에서도 판별할 수 있을까요? 한글 음차는 영문 철자와 바로 비교하기 어렵고, 약칭은 카탈로그 이름보다 짧습니다. 이름에 붙은 숫자는 비슷한 이름을 가진 서로 다른 선박을 구분하는 단서가 될 수 있습니다. 호출부호와 톤수도 함께 활용하되, 한 필드만 보고 후보를 확정하면 입력 오류의 영향을 받습니다.

이 문제를 **고정 카탈로그 대상 엔터티 매칭**으로 정의했습니다. 입력 행마다 후보를 넓게 찾은 뒤, 이름·발음과 선박 속성이 얼마나 일치하는지 순차적으로 평가해 하나의 ID를 선택합니다.

## 2. 데이터와 입력 계약

| 입력 | 역할 |
| --- | --- |
| `test.csv` | 매칭할 항만 기록. `sample_id`는 비어 있지 않고 고유해야 합니다. |
| `vessel_catalog.csv` | 정답 후보가 되는 공식 선박 카탈로그. `vessel_id` 기준으로 임베딩 및 인덱스와 연결합니다. |
| `model/train_reference.csv` | 공식 학습 자료에서 가져온 참조 테이블. 호출부호와 이름의 과거 매칭 근거를 구성합니다. |

`test.csv`에는 아래 여덟 컬럼이 필요합니다. 개별 행에서 일부 속성값이 비어 있는 경우는 전처리와 매칭 로직이 처리합니다.

| 컬럼 | 의미 | 사용 방식 |
| --- | --- | --- |
| `sample_id` | 입력 행 식별자 | 출력에 그대로 복사 |
| `vessel_name` | 관측 선박명 | 정규화, 철자·발음 검색, 임베딩, 재정렬 |
| `call_sign` | 호출부호 | 공식 학습 이력 및 카탈로그와 대조 |
| `gross_tonnage` | 총톤수 | 수치 거리와 일치 여부 |
| `international_gross_tonnage` | 국제총톤수 | 총톤수와 함께 수치 근거로 사용 |
| `flag_name` | 국적 또는 기국 표기 | 후보 속성과 비교 |
| `vessel_type` | 선종 | 후보 속성과 비교 |
| `arrival_year` | 입항 연도 | 입력 스키마에 포함 |

출력은 `sample_id,target_vessel_id` 두 컬럼의 CSV입니다. 입력 순서와 행 수를 유지하며, 예측 ID는 카탈로그에 존재해야 합니다. 제공 카탈로그와 인덱스·임베딩은 같은 버전의 자료를 사용해야 합니다.

## 3. 추론 구조

```text
항만 기록 한 행
  ├─ 호출부호 + 이름·수치 근거가 일치하면 직접 매칭
  └─ 문자·음차·별칭·임베딩으로 후보 검색
       → CatBoost 1차 랭킹 + IPA·수치 조건 보정
       → 필요한 행에 Qwen 4B 재정렬
       → 한글명과 톤수 근거가 있는 경합 사례에 전문가·보완 검색
       → 카탈로그 ID 한 개 선택
```

### 3.1 과거 이력으로 확인 가능한 행 처리

공식 Train에서 하나의 ID와만 연결된 호출부호를 조회합니다. 한글 이름이 학습 이력에 있으면 호출부호와 이름이 같은 ID를 가리키는지 확인합니다. 이름이 학습 이력에 없으면 발음·자모 유사도, 이름 속 숫자, 톤수 차이를 함께 검토합니다. 직접 매칭 근거가 부족하면 후보 검색을 진행합니다.

[학습 이력 기반 직접 매칭](model/supervised_history.py)

### 3.2 서로 다른 표현으로 후보 검색

- **문자 검색**은 정규화한 이름, 편집 거리, 문자 n-gram TF-IDF, 토큰과 약칭을 활용합니다.
- **발음 검색**은 로마자와 한글 음차, 합성 별칭, 학습된 음차 인덱스를 활용합니다. 확장 음차 경로는 한글명에 발음 후보를 추가하고, 발음 점수가 높은 후보를 최종 재정렬 목록에 보탭니다.
- **벡터 검색**은 Qwen3-Embedding-0.6B와 이름 매칭용 LoRA로 질의를 인코딩하고, 고정 카탈로그의 사전 계산 벡터와 비교합니다. 보완 검색용 임베딩은 별도 어댑터와 벡터를 사용합니다.
- **속성 비교**는 총톤수·국제총톤수의 상대 거리, 국적, 선종, 이름에 포함된 숫자의 일치와 충돌을 평가합니다.

[후보 생성](model/shipmatch_v7.py) · [확장 발음 후보](model/shipmatch_v17.py) · [이름 임베딩](model/dense_names.py)

### 3.3 CatBoost 랭킹과 IPA 보정

기본 및 증강 CatBoost 랭커가 후보를 1차로 점수화합니다. 한글명 후보에는 추가 발음·숫자 특성을 사용합니다. 최종 IPA 랭커의 입력은 **기존 후보 특성 66개 + 조합형 발음 특성 3개 + IPA 기반 특성 14개 = 83개**입니다.

IPA 특성에는 카탈로그 발음 별칭과의 코사인 유사도, 후보 간 점수 차이와 순위, 자모 편집 유사도, 이름 속 숫자의 일치 여부가 포함됩니다. 두 톤수 필드 중 하나라도 유효한 숫자면 수치 특화 모델을 사용합니다. 로더는 특성명, 특성 코드 및 모델 파일의 해시를 확인합니다.

[발음 보정](model/phonetic_calibration.py) · [IPA 특성](model/ipa_features.py) · [수치 조건 보정](model/numeric_calibration.py)

### 3.4 Qwen 4B 재정렬

라우팅 조건을 통과한 후보는 `Qwen3-Reranker-4B`와 최종 LoRA가 점수화합니다. 각 쌍의 입력은 항만 기록을 표현한 Query와 카탈로그 후보를 표현한 Document로 구성합니다. 모델은 `yes`와 `no`의 로짓 차이를 쌍의 점수로 사용합니다.

최종 설정은 보정된 1차 점수에 이름 임베딩 보조 점수와 Qwen 점수를 합산합니다. 해당 신호가 적용되는 경로의 가중치는 각각 **2.0**, **0.5**입니다. Qwen을 거친 후보의 합산 점수가 최고점과 **0.5 이내**로 가까우면 전체 프롬프트로 다시 채점합니다.

[구조화 재정렬](model/structured_reranker.py) · [점수 결합 및 근접 후보 처리](script.py)

### 3.5 전문가 재평가와 누락 후보 보완

한글 이름과 유효한 톤수가 있는 경합 사례에는 발음 전문가 LoRA를 추가로 적용합니다. 전문가와 주 모델의 점수 차이를 반영하되, 발음 근거·숫자 충돌·톤수 비교를 통해 기존 결정을 바꿀 수 있는지 확인합니다.

보완 임베딩은 1차 후보 밖의 카탈로그 항목도 검색합니다. 최대 64개 검색 결과에서 기존 목록에 없는 후보를 검토하고, 1차 점수 조건을 통과한 최대 2개를 주 모델 및 전문가로 비교합니다. 보완 후보는 점수 우위와 근거 검사를 모두 충족해야 선택됩니다.

[전문가 점수](model/post_expert.py) · [보완 검색](model/post_expert_rescue.py) · [근거 검증](model/evidence_veto.py)

## 4. 최종 Listwise40 추가 학습

이 버전에서는 A 버전 어댑터를 시작점으로 삼고, 고정 후보 풀에서 여러 후보를 함께 비교하도록 **주 재정렬 LoRA**를 추가 학습했습니다. 제출 설정은 기존 기반 모델, IPA CatBoost, 발음 전문가 및 후보 보완 경로를 유지합니다.

| 설정 | 값 |
| --- | --- |
| 추가 학습 | Listwise, 40스텝 |
| 스텝당 그룹 / 그룹당 후보 | 8 / 5 |
| 학습률 | `1e-5` |
| 마진 / Anchor MSE 계수 | 0.5 / 0.02 |
| 시드 | `2026103001` |
| LoRA rank / alpha | 32 / 64 |
| LoRA 적용 모듈 | `q_proj`, `v_proj` |

설정 파일에는 어댑터, 학습 프로토콜 및 고정 데이터 매니페스트의 SHA-256이 기록되어 있습니다. 첨부 제출본에는 추론 코드와 학습된 자산이 들어 있으며, 추가 학습을 다시 실행하는 코드나 고정 후보 그룹은 제공되지 않았습니다.

## 5. 평가 결과와 해석

| 구분 | 값 | 해석 |
| --- | ---: | --- |
| Listwise40 추가 학습 진단 | 247 / 256 · 96.4844% | 공식 Train에서 구성한 진단 세트의 정답률 |
| 진단에서 개선 / 악화된 행 | 1 / 0 | 설정에 기록된 비교 결과. 예측 ID가 바뀐 행은 총 2건 |
| 1차 후보 적중 | 189건 | 같은 진단의 후보 적중 건수 |
| 후보 적중 시 결합 Top-1 | 97.8836% | 후보 적중 부분집합에서의 조건부 지표 |
| 이전 A 버전 Public | 0.9715 | 설정에 남은 사용자 보고값 |
| 최종 Listwise40 공식 점수 | 미측정 | 제출 설정의 `official_score`는 `null` |

진단에 포함된 선박은 이전 랭커, 조회 테이블, 임베딩 등 상위 단계의 학습 자산이 이미 접했을 수 있습니다. 따라서 **96.48%는 추가 학습의 개발 진단**입니다. 설정에 남은 Family0/V40 결과도 이전 단계의 개발 기록이며, Family1 확인과 최종 버전의 새 L4 전체 실행 시간 측정은 완료되지 않았습니다. 이전 A 버전의 Public 점수는 최종 Listwise40 성능과 구분합니다.

## 6. 오프라인 실행과 처리량

모델과 토크나이저는 로컬 파일에서 읽고, 추론 중 외부 API를 호출하지 않습니다. CPU는 후보 생성과 CatBoost 점수화를 준비하고, 제한된 큐를 통해 GPU 재정렬 작업을 전달합니다. Qwen 경로는 고정 지시문 및 동일 질의의 KV 상태를 재사용하며, 프롬프트가 캐시 경로의 조건을 만족하지 않으면 전체 채점 경로를 사용합니다. 각 행의 결정은 해당 행의 입력과 고정 카탈로그에 근거하며, 배치 처리는 평가 행들 사이의 통계를 특성으로 사용하지 않습니다.

원본 모델의 대용량 가중치는 `SHIPWGT1` 형식으로 보관됩니다. 최초 실행 시 블록을 복원해 원본 바이트 수, SHA-256, CRC32를 확인합니다. 이 과정은 저장용 무손실 복원입니다. 세 기반 가중치의 복원 크기는 합계 약 **9.24 GB**이며, 압축 파일과 복원본을 함께 유지할 디스크 공간이 필요합니다.

[KV 재사용](model/prefix_v6.py) · [가중치 복원 코드](model/weight_storage.py) · [가중치 매니페스트](model/packed_weights/manifest.json)

## 7. 실행 방법

GitHub용 패키지에는 추론 소스, 설정과 검증 매니페스트를 담았습니다. 실제 예측에는 **원본 제출 ZIP에서 압축을 푼 전체 `model/` 폴더**와 **공식 `test.csv`, `vessel_catalog.csv`**가 필요합니다. 데이터와 모델 경로를 직접 지정할 수 있습니다.

```bash
python script.py --data-dir /path/to/official-data --model-dir /path/to/submission/model --output-path output/submission.csv
```

경로 인자를 생략하면 진입점 옆의 `data/`, `model/`, `output/submission.csv`를 사용합니다. 기본 설정은 동봉 IPA CatBoost를 로드합니다. 비교할 때 `--original-v40`은 기본 IPA 번들 선택을 끄는 옵션이며, 주 LoRA를 이전 버전으로 교체하지는 않습니다.

제출본의 `requirements.txt`는 대회 사전 설치 환경을 전제로 합니다. 코드에서 확인한 주요 의존성은 PyTorch, Transformers, safetensors, CatBoost, NumPy, pandas, SciPy, scikit-learn, joblib, RapidFuzz, Unidecode, threadpoolctl입니다. 별도 환경에서는 특히 Transformers의 KV 캐시 API와 직렬화된 인덱스의 호환성을 확인해야 합니다. 첨부 자료에는 정확한 의존성 버전 목록이 없습니다.
